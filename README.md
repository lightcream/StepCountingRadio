# Neon Step Media Player

纯前端、本地运行、适合 GitHub Pages 的媒体播放器。媒体/字幕/音乐都使用浏览器本地 `File` + `Object URL`，不会上传到服务器。

## GitHub Pages 部署

1. 新建 GitHub 仓库。
2. 上传 `index.html`、`styles.css`、`app.js`。
3. 在 **Settings → Pages** 里选择 `Deploy from a branch`，分支选择 `main`，目录选择 `/ (root)`。
4. 保存后等待 GitHub Pages 发布即可。

因为计步、传感器权限、Speech Synthesis 和部分 Web Audio 能力要求安全上下文，所以建议直接使用 GitHub Pages 的 HTTPS 地址访问，不要用普通 HTTP。

## 功能逻辑

### 1. 几 GB 大视频

播放器不把视频读进 JS 内存，也不做前端转码；直接使用浏览器原生媒体管线播放本地 `File` 对象。这样避免一次性复制整个文件。原生解码器负责 H.264/H.265/AV1、不同帧率和关键帧 seek 能力，实际支持程度仍取决于浏览器/系统解码器。

### 2. 计步播放时间

网页端目前没有一个跨平台统一的“系统计步计数器”API，因此代码优先尝试 Generic Sensor `Accelerometer`，不支持时回退到 `DeviceMotionEvent`，用加速度模长峰值做步态检测。iOS 等平台会在第一次开启时请求运动权限。

每次识别一步：
- 没有正在消耗播放时间 → 立即增加一段播放时间。
- 当前剩余时间大于“结算窗口” → 不叠加。
- 当前剩余时间进入“结算窗口” → 只记一个 `pendingStep`。
- 播放时间结束后，如果有 `pendingStep`，只激活一次新的播放时间。

`预热 2:15` 则直接提供 135 秒播放时间。

### 3. 字幕 + TTS

支持：JSON、LRC、VTT。

工作流：媒体进度到达字幕 `from` → 暂停 → `speechSynthesis` 朗读中文 → 从 `from` 原点播放该字幕片段至 `to` → 清除字幕 → 正常推进到下一段。没有字幕的时间段不会调用 TTS。

移除字幕即可恢复普通播放。

### 4. 音乐律动跳跃

音乐通过 Web Audio `AnalyserNode` 获取频谱能量，计算相邻分析窗口的能量突增（spectral flux 风格的简化检测）。当突增超过自适应阈值且距离上一次跳跃超过冷却时间时，触发随机跳跃。

跳跃目标可以：
- 落在当前媒体的前面或后面；
- 随机切换到播放列表中的另一媒体；
- 绕开每个媒体的“开头 N 分钟”和“结尾 N 分钟”；
- 通过“跳跃冷却”限制连续跳跃，避免一秒数十次导致闪烁。

这是“节拍驱动随机切镜”的浏览器端轻量方案，不依赖服务器转码，也没有固定 BPM 标记的前提。真正专业的离线 beat tracking 可以进一步替换成更强的 onset/beat 算法，但当前方案更适合纯 GitHub Pages。

### 5. 全屏

全屏使用自定义播放器容器的 Fullscreen API。暂停时不展示默认暂停标志；自定义进度条在普通状态和全屏状态都可操作。全屏跳跃时会闪动底部进度条，并在浏览器允许时进行短震动。

### 6. 播放速度

速度作为全局状态保存到 `localStorage`，每次媒体 `loadedmetadata` 和定时同步都会重新应用，因此切换/新增视频不会重置倍速。`[` 与 `]` 可以在非输入框聚焦时以 0.05× 调整速度，也可以直接输入数值。

## 兼容性说明

浏览器能否解码某一种编码，并不是网页代码可以完全保证的。特别是某些 HEVC/H.265、AV1、10-bit、专业容器或少见音频编码，在不同操作系统上支持差异较大。对于本地资源，网页只能尽量把解码交给系统/浏览器原生媒体栈。

计步传感器也存在平台差异：桌面浏览器通常没有真实步数传感器；移动端需要 HTTPS、用户授权，并可能因为浏览器后台策略而暂停传感器事件。页面里保留了预热按钮作为无需计步的备用入口。
